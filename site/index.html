不用打卡，回头一看都在

常驻进程在后台记录，你照常工作。想知道时间去哪了、那条命令是什么、上周做到哪了，随时问它。

focus窗口时段

焦点在哪个窗口、标题是什么、待了多久。标题里一直在变的部分会被去掉，不会把时段切碎。

afk离开不算数

几分钟没碰键盘鼠标就算离开，所有时长都扣掉这段时间。窗口开着但人不在，不算。

timeline上下文在一起

时间线每一段下面直接列出期间执行的命令和看过的网页：不只是开着哪个窗口，还有当时在干什么。

project按项目算

项目目录、命令的工作目录、niri 工作区名、浏览器 profile，都能把活动归到项目。

search找得回来

窗口标题、命令、网页全文检索，中文不需要词典。摘要和笔记还能按意思找，用的是本机模型。

summary每日回顾

每天凌晨把前一天写成一份 Markdown：按项目、时间线要点、没做完的事。可以手改，可以被检索。

tui终端界面

lifelog-tui：日、时间线、命令、网页、周、搜索，左右键翻天。

json给脚本用

管道里输出稳定的 JSON，退出码遵循 sysexits，和 jq 配合正好。

mcp给 agent 用

附带 Claude Code skill 和 MCP 服务：「我上周在这个项目上做了什么？」直接问。

记录的是你，所以数据只属于你

没有账号、没有云端、没有遥测。每条记录写进数据库之前，先经过隐私处理。

  1. 从本机读niri 的 IPC、Wayland 空闲通知、atuin 和浏览器已经保存的历史。不记按键、剪贴板、屏幕。
  2. 归到项目按路径、工作区、profile 和你写的规则。
  3. 排除和脱敏密码管理器、隐私窗口只记时长；pass 这类命令只记时刻；看起来像密钥的片段换成 [redacted]。
  4. 写进本机的 SQLite~/.local/share/lifelog/lifelog.db，一个文件，删掉就没了。

会离开本机的，只有这些

每日摘要的原料只在你配置了模型时，发给你选的接口。--dry-run 先看。
agent 查到的内容发给那个 agent 的服务商。可以只对 agent 隐藏某些来源。
嵌入模型第一次按意思检索时下载，之后完全离线。

发给模型的原料里只有网页标题和域名，没有完整网址。

一切都是组件

kernel 只管生命周期、命名和消息传递。窗口管理器、数据库、模型、每一个功能，都是通过契约通信、可以单独关掉或替换的组件。

加功能 = 加组件

新建一个包、在启动器里加一行依赖。不改 kernel，不改别的组件，没有手写的注册表。

换实现 = 换组件

想支持另一个窗口管理器？写一个提供 Windows 契约的组件，通过同一份契约测试。

规则由工具检查

依赖方向由架构测试检查，契约只能传纯数据由编译器检查，配置文档和默认值由测试对照。
